# Supabase Phase 1 Schema Sketch (Pixel Office)

High-level, relational-first sketch for the initial backbone. This is not final SQL, but close enough to turn into migrations.

## 1. agents

Represents an agent/persona in the office.

- `id` (uuid, pk)
- `created_at` (timestamptz, default now())
- `name` (text)
- `role` (text) — e.g., "scrum_master", "observer", "cooler_regular"
- `avatar` (text, nullable) — URL or asset id
- `metadata` (jsonb, nullable) — model, temperature, speciality, etc.

## 2. sessions

A logical conversation or working session (cooler talk, scrum, etc.).

- `id` (uuid, pk)
- `created_at` (timestamptz, default now())
- `updated_at` (timestamptz, default now())
- `kind` (text) — e.g., "cooler", "scrum", "github_review", "benchmark"
- `title` (text, nullable)
- `status` (text) — e.g., "active", "completed", "archived"
- `context` (jsonb, nullable) — seed prompt, repo refs, tags

## 3. events

Generic time-ordered events within a session (messages, state changes, decisions).

- `id` (uuid, pk)
- `created_at` (timestamptz, default now())
- `session_id` (uuid, fk → sessions.id)
- `agent_id` (uuid, fk → agents.id, nullable) — null for system events
- `type` (text) — e.g., "message", "state_change", "decision", "error"
- `payload` (jsonb) — body, diffs, metadata

## 4. tasks

Actionable work items generated by office activity.

- `id` (uuid, pk)
- `created_at` (timestamptz, default now())
- `updated_at` (timestamptz, default now())
- `source_session_id` (uuid, fk → sessions.id, nullable) — where it came from
- `title` (text)
- `description` (text)
- `status` (text) — e.g., "todo", "in_progress", "done", "dropped"
- `priority` (text, nullable) — e.g., "low", "medium", "high"
- `tags` (text[] , nullable)
- `assignee_id` (uuid, fk → agents.id, nullable)

## 5. cooler_sessions

Specialization of `sessions` focused on cooler talk, with extra metadata.

- `id` (uuid, pk, fk → sessions.id) — 1–1 with sessions
- `topic` (text, nullable)
- `relevance_score` (numeric, nullable) — threshold for promotion to SCRUM/Task
- `is_scrum_candidate` (boolean, default false)

## 6. cooler_messages

Individual cooler talk messages.

- `id` (uuid, pk)
- `created_at` (timestamptz, default now())
- `cooler_session_id` (uuid, fk → cooler_sessions.id)
- `agent_id` (uuid, fk → agents.id)
- `content` (text)
- `sentiment` (text, nullable)
- `tags` (text[], nullable) — e.g., ["burnout", "tooling", "productivity"]

## 7. scrum_runs

Represents a structured SCRUM or follow-up session.

- `id` (uuid, pk)
- `created_at` (timestamptz, default now())
- `source_cooler_session_id` (uuid, fk → cooler_sessions.id, nullable)
- `source_session_id` (uuid, fk → sessions.id, nullable)
- `title` (text)
- `status` (text) — e.g., "planned", "running", "completed"
- `summary` (text, nullable)

## 8. scrum_stage_events

Timeline of key SCRUM moments (planning, standup, review, etc.).

- `id` (uuid, pk)
- `created_at` (timestamptz, default now())
- `scrum_run_id` (uuid, fk → scrum_runs.id)
- `stage` (text) — e.g., "intake", "planning", "standup", "retro"
- `payload` (jsonb) — notes, extracted action items, etc.

## 9. artifacts

Stored outputs: summaries, diagrams, exports, files.

- `id` (uuid, pk)
- `created_at` (timestamptz, default now())
- `session_id` (uuid, fk → sessions.id, nullable)
- `scrum_run_id` (uuid, fk → scrum_runs.id, nullable)
- `task_id` (uuid, fk → tasks.id, nullable)
- `kind` (text) — e.g., "markdown_summary", "mermaid_diagram", "json_export", "screenshot"
- `storage_path` (text) — Supabase Storage path or external URL
- `metadata` (jsonb, nullable)

---

## Relationships Summary

- `agents` participate in `sessions` via `events` and `cooler_messages`.
- `sessions` can specialize into `cooler_sessions` and connect to `scrum_runs`.
- `cooler_sessions` → can flag `is_scrum_candidate` and spawn `scrum_runs` and/or `tasks`.
- `scrum_runs` generate `scrum_stage_events` and `artifacts`.
- `tasks` can be spawned from sessions, cooler talk, or scrum runs.

This is a **Phase 1 sketch**: good enough to start migrations and a first Supabase project, and easy to extend later with `repo_queries`, `benchmark_runs`, and `model_role_mappings` once the backbone is stable.
